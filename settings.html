Страница **ждёт `onAuthStateChanged()`**, и только после получения Firebase-пользователя обращается к `users/{uid}`. Но есть **очень важный момент**: если твоя страница входа находится на `kurator-jurnal.pages.dev`, а вход выполняется с другим `authDomain`, либо на странице входа используется **другой Firebase project/config**, эта страница всё равно будет получать `null`. Проверь в консоли на **странице входа**: ```js console.log(auth.currentUser); ``` и на `/settings`: ```js console.log(auth.currentUser); ``` У них должны быть один и тот же Firebase project и один и тот же UID. Для твоего пользователя UID из Firestore: ```text lvqxwDFeNHcU3LmdDh9PhGMOAi03 ``` Поэтому после авторизации на `/settings` в консоли должно появиться примерно: ```text Firebase Authentication user: { uid: "lvqxwDFeNHcU3LmdDh9PhGMOAi03", email: "vasylkivmaksim@gmail.com", ... } ``` А затем: ```text Firestore profile: { email: "vasylkivmaksim@gmail.com", group: "214", name: "Васылькив Максим Владимирович", role: "admin", uid: "lvqxwDFeNHcU3LmdDh9PhGMOAi03" } ``` И тогда откроется интерфейс администратора с группами. **Если после замены файла всё ещё будет `auth.currentUser = null`, проблема уже находится в `index.html` — странице входа.** Тогда нужно переделать **код авторизации в `index.html`**, чтобы он использовал абсолютно тот же `firebaseConfig`, `getAuth(app)` и `browserLocalPersistence`. Именно это позволит сессии нормально переходить с `index.html` на `/settings`.
